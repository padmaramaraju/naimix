Integrations

An integration describes how to call one backend operation and how to reshape its response. It has three parts: input, backend and output.

Anatomy

id: sql-customer-by-id
description: Fetch a single customer from the demo SQLite database.

input:
  - name: id
    in: path            # path | query | header | body | env
    required: true
    type: string        # string | number | boolean

backend:
  type: sql
  gateway: demoDb
  query: SELECT id, first_name, last_name, city, status FROM customers WHERE id = :id

output:
  fields:
    - target: customerId
      source: $[0].id
    - target: name.first
      source: $[0].first_name
    - target: location.city
      source: $[0].city
    - target: active
      source: $[0].status
      transform: toString

Input parameters

FieldMeaning
nameParameter name, used as {name} (or :name in SQL).
inpath, query, header, body, or env.
requiredMissing required input returns a 400.
typestring, number or boolean.
defaultUsed when the parameter is absent.
envVarFor in: env: which variable to read. Defaults to name.

Environment parameters (in: env) are never read from the caller. They come from the server's own environment, so shared secrets such as a backend API key never reach or get overridden by callers.

Backend types

json

backend:
  type: json
  gateway: crmJson
  url: /customers/{id}
  method: GET
  headers: {}
  query: {}
  body: null
  timeoutMs: 10000

xml

backend:
  type: xml
  gateway: crmXml
  url: /customers/{id}/xml
  method: GET

The parsed object mirrors the XML tags, rooted at the outermost tag: <customer><id>2</id></customer> becomes { customer: { id: "2" } }, so sources start $.customer…. Attributes get an @_ prefix ($.customer['@_id']). All values are strings; add transform: toNumber where needed.

Single-item collections: the parser only produces an array when a tag repeats two or more times. If your backend can return exactly one item, make sure it still wraps it consistently.

soap

backend:
  type: soap
  gateway: crmSoap
  operation: GetCustomer
  args:
    CustomerId: "{id}"
  # endpoint: https://real-service.example.com/CustomerService   # optional override

Many WSDLs advertise a stale <soap:address>, so the call goes to the WSDL URL with its query string stripped unless you set endpoint.

sql

backend:
  type: sql
  gateway: demoDb
  query: "SELECT id, first_name FROM customers WHERE id = :id"

Use named :param bindings matching your input names. For table-wide CRUD, see Generated CRUD endpoints.

Output mapping

The output is one JSON object built from output.fields, evaluated against the whole backend response. Use $[0].field when the backend returns a top-level array, as SQL does.

FieldMeaning
targetDot-path in the JSON you return. Supports nesting (name.first) and indices (tags[0]).
sourceJSONPath into the backend response.
defaultUsed when source matches nothing.
transformtoString, toNumber, toBoolean, trim, upper, lower, or a custom function.

Arrays

output:
  fields:
    - kind: array
      target: customers       # response becomes { "customers": [...] }
      root: $[*]              # JSONPath selecting the array
      fields:
        - target: id
          source: $.id
        - target: name
          source: $.firstName

A nested array's own root is relative to its parent item, to any depth.

Validation

Config files are validated on load with zod. A malformed file is logged and skipped, so one bad file never takes down every other integration.
