Transform functions

When the built-in transforms are not enough, write a small function to modify one value, add or remove fields, or rewrite a whole mapped result.

Two hook points

HookWhereSignature
Field-levelA field's transform(value, ctx) => value | undefined. Returning undefined omits the field.
Integration-leveloutput.postProcess(data, ctx) => data. Runs once on the entire mapped result, after every field is extracted.

ctx carries { item, raw, params }: the current item, the raw backend response, and the resolved input parameters.

output:
  postProcess:
    name: addFullName
  fields:
    - target: firstName
      source: $.first
      transform:
        kind: function
        name: titleCase

Where functions live

Functions are real files in the workspace: <workspace>/transforms/<name>.ts (source) and <name>.js (compiled CommonJS, which is what actually runs). Configs refer to them purely by name. Because the workspace is usually its own Git repo, functions travel with integrations and gateways.

Writing one in the console

  1. Open an integration and go to the Output tab.
  2. In a field's Transform picker (or the post-process picker), choose + New function….
  3. Name it, write the code, type a sample value, and click Test.
  4. Save. The function is written to the workspace's transforms/ folder and can be reused by name anywhere.

Rules

  • Functions are pure and synchronous: no async/await, and no network or database calls.
  • Deleting a function that an integration still references is refused with a 409.

Dev vs. QA/Production

BuildBehavior
Developer ConsoleCode editor (TypeScript or plain JS) with a Test button that compiles and runs your function against sample input. Changes take effect without a restart.
QA / ProductionFunctions load once at startup from transforms/*.js. Nothing reloads them. A change requires a restart.

Security trade-off: before this feature, pulling workspace changes and reloading could only change data, since YAML cannot execute anything. Now a pull plus restart on QA or Production can run new code. Whoever can push to the workspace repo can change what runs, so protect that branch accordingly.
